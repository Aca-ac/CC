# Chronos 架构说明

## 总体结构

Chronos 采用“客户端 + 服务端 + AI 服务”的三层架构。客户端优先保证本地任务管理可用；服务端负责认证、云端持久化、同步协调和 AI 调度；AI 服务只作为增强能力，不影响核心清单功能。

```text
用户
  │
  ├─ Electron 桌面客户端 / PWA
  │    ├─ React 页面与组件
  │    ├─ 本地 SQLite 数据
  │    └─ 同步队列
  │
  └─ HTTPS / REST API
       │
       └─ Spring Boot 后端
            ├─ 认证与权限
            ├─ 项目与任务业务
            ├─ 统计与看板
            ├─ 本地-云端同步
            └─ AI 草稿生成调度
                 │
                 └─ 第三方 LLM API（后续接入）
```

## 模块边界

- `client/`：负责用户交互、页面状态、Mock 展示、Electron 桌面壳和 PWA 基础能力。
- `server/`：负责 REST 接口、业务规则、统一响应、认证占位和后续 MySQL 持久化。
- `database/`：给出 SQLite 与 MySQL 的首版表结构草案，保证团队讨论字段时有共同起点。
- `docs/`：记录架构、接口、数据库和协作规范，避免开发时只依赖口头说明。

## 优先级落地

- P0：认证、项目管理、任务 CRUD、任务状态流转、今日看板、本地持久化、基础同步、基础统计。
- P1：AI 智能拆解、任务树预览、学习日志、习惯打卡、番茄钟、周视图、课程表导入和统计看板。
- P2：RAG 长期记忆、复杂提醒、防干扰模式、专注评分和更完整的资料库。

## AI 降级原则

AI 能力必须保持“可关闭、可失败、可替换”。前端只展示草稿，后端只在用户授权后组装必要上下文。AI 服务不可用时，用户仍能手动创建项目、任务、日志和打卡记录。

## 同步原则

课程项目阶段先采用触发式或定时 REST 同步，不引入 WebSocket、消息队列或分布式中间件。客户端本地写入成功后加入同步队列；网络恢复后后端根据版本号和更新时间判断是否接受或提示冲突。
