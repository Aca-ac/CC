# Chronos 开发指南

## 分工建议

- 前端核心开发：负责 `client/src/pages/tasks`、任务卡片、状态流转和番茄钟交互。
- 前端扩展开发：负责日历、日志、统计图表、PWA 适配和响应式细节。
- 后端核心开发：负责项目、任务、同步和数据库访问。
- 后端业务开发：负责认证、权限、AI 调度和 Prompt 模板。
- 测试与运维：负责 CI、接口测试、构建脚本、部署文档和验收用例。

## 注释规范

- 业务占位代码用 `TODO(负责人/模块):` 标明后续任务。
- 与需求文档直接对应的模块，在注释中标注 FR 或 UC 编号。
- 不要把注释写成逐行翻译，重点说明业务原因、边界和后续接入点。

## 提交规范

- `chore:` 工程配置、脚手架、依赖和文档维护。
- `feat:` 新增用户可见功能。
- `fix:` 修复缺陷。
- `docs:` 只修改文档。
- `test:` 新增或修改测试。

## 开发顺序建议

1. 先让 `GET /api/health`、前端首页和 CI 全部跑通。
2. 后端实现项目和任务的最小 CRUD，前端用真实接口替换 Mock。
3. 增加登录和 Token 拦截器，但保留本地模式或演示账号。
4. 完成今日看板、任务状态流转和基础统计。
5. 增加 AI 草稿接口，先接 Mock，再接真实供应商。
6. 最后补同步冲突、导出周报、课程表导入和更完整的验收测试。
