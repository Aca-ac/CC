# 2 任务概述

## 2.1 目标

Chronos 的总体目标是开发一个工具优先、AI 可选的智能学习任务管理系统。用户在不使用 AI 的情况下仍可完成学习项目创建、任务管理、日历查看、日志记录、习惯打卡、专注计时和统计分析；当用户配置 AI 能力后，系统可进一步提供学习目标拆解、任务自动生成、阶段性复盘和个性化调整建议。

- 目标拆解：将长期或阶段性目标转换为学习路径、任务树、阶段计划和每日安排。

- 原子化执行：把颗粒度过大的任务拆分为一次专注可完成的原子任务，并高亮当前最应执行的下一步动作。

- 执行管理：支持任务创建、编辑、删除、状态流转、优先级管理、日历与看板展示。

- 过程记录：支持学习日志、资料链接、番茄专注记录、习惯打卡等过程数据沉淀。

- 反馈复盘：通过数据看板、延期风险提示和 AI 周期诊断帮助用户发现投入不足、计划过载或任务拆解不合理的问题。

- 多端与离线：桌面端作为核心载体，PWA 作为移动端轻量访问入口，本地优先并支持云端同步。

## 2.2 用户特点

  ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------

  --------------------------- -------------------------------------------------------------------------------- --------------------------------------------------------------

  重度计划用户                已习惯使用清单、日历或笔记工具，对视图切换、标签、筛选、统计有较高要求。         多视图切换、批量操作、数据导出、灵活标签和优先级管理。

## 2.3 软件产品与外部环境关系

Chronos 与外部环境的关系如下：用户通过桌面客户端或 PWA 操作系统；客户端优先写入本地 SQLite；客户端通过 HTTPS/REST API 与云端 Spring Boot 服务通信；云端服务负责用户认证、任务业务逻辑、同步调度、统计分析和 AI 调度；AI 模块调用第三方 LLM API；日历导入模块读取 iCal/外部日历数据源。

## 2.4 假定与前提

- 用户具备基本的电脑和移动端浏览器使用能力，能够理解任务、项目、截止时间、优先级等概念。

- 桌面端运行设备可安装并运行 Electron 客户端，移动端至少可通过现代浏览器访问 PWA 页面。

- AI功能属于增强能力，用户可配置第三方 LLM API Key 或由系统配置统一服务；未配置或调用失败时，核心清单功能仍可使用。

- 课程项目周期有限，系统首先保证 P0 核心功能可交付，P1/P2 功能按开发进度逐步实现。

- 系统处理的学习目标、日志、任务内容属于个人数据，应采用最小化采集、加密传输和必要脱敏策略。

## 2.5 系统边界与优先级

  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **优先级**    **范围**                                                                                                 **说明**
  ------------- -------------------------------------------------------------------------------------------------------- -----------------------------------------------------------
  P0 必须实现   注册/登录、学习项目管理、任务 CRUD、任务状态流转、今日看板、本地持久化、基础同步、基础统计。             构成系统最低可用版本，验收时必须稳定运行。

  P1 应当实现   AI 智能拆解、任务树预览、AI 优化建议、学习日志、习惯打卡、番茄钟、周视图、课程表导入、AI拆解质量反馈。   体现 Chronos 与普通清单工具的差异化价值，应优先纳入演示。

  P2 可选实现   资料库、更多主题、深度 RAG 长期记忆、复杂提醒策略、电脑使用时长统计、专注评分、防干扰模式。              根据时间和技术条件实现，不影响核心验收。

                 A3. 用户选择"拒绝结果"，系统不保存 AI 生成内容，并提供手动创建入口。\
                 A4. 用户只接受部分任务时，系统仅保存被勾选条目。

    **异常流**   E1. AI服务超时或限流时，系统提示稍后重试，并保留用户输入内容。\
                 E2. AI返回结果结构不完整、层级过深或逻辑明显冲突时，系统提示"生成结果需要重新整理"，并提供重新生成或手动编辑。\

                 E4. 用户取消隐私授权时，系统不调用 AI 服务。

   **业务规则**  R1. AI生成结果必须经过用户确认才能写入正式任务。\
                 R2. AI功能不可用不得影响用户手动创建项目和任务。\

   外部服务输出          第三方LLM返回的学习路径、任务建议、复盘摘要。           需结构化解析和安全校验；用户确认后方可落库。     形成草稿方案、AI建议或任务调整。

## 3.5 其他要求

### 3.5.1 界面要求

- 整体风格应简洁、明亮、现代，采用一致的圆角、卡片、阴影、图标和色彩层级。

- 核心页面必须包括今日学习看板、项目详情、任务编辑、AI智能拆解、统计看板和设置页面。

- 信息层级应清晰，高频操作入口突出，避免在单页堆叠过多低频配置。

- 图表与状态标识使用一致颜色语义，例如高优先级、进行中、已完成、延期等状态应可快速辨识。

- AI生成内容必须以"预览/草稿"方式呈现，用户确认前不得自动创建正式任务。

- AI生成结果应提供接受、继续优化、手动编辑、拒绝和质量反馈入口，避免让用户被动接受模型输出。

### 3.5.2 进度要求

项目最迟完成时间为 2026年6月。需求文档应在需求评审前完成，系统设计文档、数据库设计和接口文档应在编码主要阶段前形成基线，核心功能应优先于扩展功能实现。
